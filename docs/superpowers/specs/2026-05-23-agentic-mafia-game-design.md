# Agentic Mafia Game — Design Spec

- **Date**: 2026-05-23
- **Status**: Draft, awaiting user approval
- **Owner**: kimjaehyun9605@gmail.com

## 1. 개요

사용자 1명과 AI 에이전트 3~10명이 한 판에 어울려 플레이하는 웹 기반 마피아 게임. AI 에이전트는 각자 고정 페르소나(50개 풀에서 랜덤 추출)를 갖고 Claude API (Haiku 4.5) 로 구동된다. 게임 진행은 백엔드 상태머신이 차례를 통제하고, 사용자는 차례 발언과 더불어 자유 발언 페이즈에서 "끼어들기" 버튼으로 흐름에 진입한다.

## 2. 목표 / 비목표

**목표**
- 한국식 마피아 게임 1판을 끝까지 즐길 수 있는 단일 플레이 웹 게임
- AI 에이전트의 페르소나·역할이 일관되게 유지되어 추리·설득이 의미를 가짐
- 인원 4~11명 가변 지원, 인원에 따라 역할 구성이 자동 조정
- 비용 효율 (Haiku 4.5 + prompt caching) 로 한 판 운영비를 합리적 수준으로 유지

**비목표**
- 멀티플레이어 (사람 vs 사람) 모드
- 모바일 네이티브 앱
- 영구 계정·랭킹·리플레이 저장 (MVP 범위 밖)
- 음성/TTS

## 3. 게임 룰

### 3.1 인원과 역할 배정
시작 메뉴에서 4~11 사이 인원을 선택. 사용자 1명 포함.

| 인원 | 마피아 | 경찰 | 의사 | 특수 | 시민 |
|------|--------|------|------|------|------|
| 4    | 1      | 1    | 0    | 0    | 2    |
| 5    | 1      | 1    | 0    | 0    | 3    |
| 6    | 2      | 1    | 1    | 0    | 2    |
| 7    | 2      | 1    | 1    | 0    | 3    |
| 8    | 3      | 1    | 1    | 1    | 2    |
| 9    | 3      | 1    | 1    | 1    | 3    |
| 10   | 4      | 1    | 1    | 2    | 2    |
| 11   | 4      | 1    | 1    | 2    | 3    |

- 사용자 역할은 모든 역할에 랜덤 배정 가능 (사용자가 마피아일 수 있음).
- 마피아 ≥ 2일 때 마피아 중 1명이 두목(boss)으로 지정, 나머지는 부하(underling). 사용자가 마피아이면 두목/부하 랜덤.
- 특수 역할: 8명 이상일 때 사용. 후보 — `성직자` (1차 투표 및 찬반 투표 모두 2표, 정체는 본인만 알고 결과 발표에는 표시되지 않음 — 다른 사람은 득표 합산을 보고 추리), `연인` (지명된 사람과 동반 사망), `기자` (투표 결과 익명 공개) 중 인원수에 따라 1~2개 선택. (구현 우선순위: `성직자` → `기자` → `연인`)

### 3.2 승리 조건
- **시민측 승**: 마피아 전원 사망
- **마피아측 승**: 마피아 수 ≥ 비마피아 생존자 수

### 3.3 페이즈 흐름 (상태머신)

```
LOBBY
  ↓ (게임 시작)
NIGHT
  ↓
DAY_ROUNDROBIN
  ↓
DAY_FREETALK
  ↓
VOTE_NOMINATE
  ↓ (최다 득표자 존재)
LAST_WORDS
  ↓
VOTE_UPDOWN
  ↓
CHECK_WIN ──→ GAME_OVER
  ↓ (승부 미결정)
NIGHT (반복)
```

동률 등으로 처형 후보가 없으면 `LAST_WORDS`, `VOTE_UPDOWN` 을 건너뛰고 바로 `CHECK_WIN` → `NIGHT`.

### 3.4 밤 페이즈 (NIGHT)
순차 처리:
1. **마피아 타겟 결정**
   - 마피아 1명: 단일 에이전트가 `night_action {target_id}` 반환
   - 마피아 ≥ 2:
     1. 두목이 마피아 단톡에서 타겟과 이유 발표
     2. 각 부하가 순차로 `{agree: yes/no, reasoning}` 표명
     3. 전원 동의 → 타겟 확정
     4. 1명 이상 반대 → 반대한 각 부하와 두목이 2~3턴 대화
     5. 두목의 최종 결정으로 타겟 확정 (부하 거부권 없음)
2. **의사 보호 대상 결정** (의사 존재 시): 의사 에이전트가 `{target_id}` 반환 (자기 자신 가능 여부 — 가능)
3. **경찰 조사 결정** (경찰 존재 시): 경찰 에이전트가 `{target_id}` 반환. 결과 = 해당 대상이 마피아인지 여부, 비공개로 경찰 메모리에 저장
4. **사망 처리**: 마피아 타겟 == 의사 보호 대상 → 생존. 아니면 사망.

사용자가 마피아/경찰/의사일 때는 UI 패널을 통해 동일 흐름 참여 (마피아면 단톡창, 경찰/의사면 타겟 선택 모달).

### 3.5 낮 토론 페이즈

**DAY_ROUNDROBIN**: 모든 생존자(AI + 사용자)가 한 번씩 발언. 순서는 발언 욕구 점수(§5.4) 내림차순. 사용자는 자신의 차례에 입력. AI의 발언은 스트리밍으로 채팅창에 표시.

**DAY_FREETALK**: 최대 2 라운드. 각 라운드마다 AI들의 욕구 점수를 재계산해 상위 1~2명만 추가 발언. 사용자는 언제든 "끼어들기" 버튼으로 진입 — 백엔드는 다음 AI 디스패치를 멈추고 사용자 입력을 받음. 사용자 발언 후 자유 발언 이어짐.

### 3.6 투표 페이즈

**VOTE_NOMINATE**: 각 생존자가 처형 후보 1명 지목. 최다 득표자가 후보 (동률 → 처형 없음, 곧장 `CHECK_WIN`).

**LAST_WORDS**: 후보자가 마지막 발언.

**VOTE_UPDOWN**: 후보자를 제외한 생존자가 찬성(UP) / 반대(DOWN) 투표. 찬성 > 반대 → 처형. 아니면 생존.

## 4. 아키텍처

```
┌─────────────────────┐         ┌──────────────────────────┐
│  Next.js (Web UI)   │ ←WS→   │  FastAPI Backend         │
│  - 채팅창           │         │  ┌────────────────────┐  │
│  - 마피아 단톡(밤)  │         │  │ GameEngine         │  │
│  - 투표 버튼/모달   │         │  │ (FSM)              │  │
│  - 끼어들기 버튼    │         │  └────────────────────┘  │
│  - 생존자 패널      │         │  ┌────────────────────┐  │
└─────────────────────┘         │  │ AgentManager       │  │
                                │  │ - 페르소나 풀(50)  │  │
                                │  │ - 에이전트 메모리  │  │
                                │  └────────────────────┘  │
                                │  ┌────────────────────┐  │
                                │  │ ClaudeClient       │  │
                                │  │ (Haiku + caching)  │  │
                                │  └────────────────────┘  │
                                └──────────────────────────┘
```

### 4.1 WebSocket 이벤트

**서버 → 클라이언트**:
- `phase_change {phase, day_number}`
- `agent_speak {agent_id, text, channel}` (스트리밍 청크 단위, `channel` = `public` | `mafia`)
- `system_message {text}` (사망 알림, 페이즈 안내 등)
- `vote_open {type: nominate|updown, candidates|candidate, deadline_hint}`
- `vote_result {tally, outcome}`
- `night_action_request {role, choices}` (사용자가 해당 역할일 때)
- `death {agent_id, reason}`
- `game_over {winner, summary}`

**클라이언트 → 서버**:
- `user_speak {text}` (라운드로빈 차례 또는 끼어들기 후)
- `user_interrupt` (자유 발언 중)
- `user_vote {target_id}` / `user_updown {yes|no}`
- `night_action {target_id}` (마피아·경찰·의사)
- `mafia_chat {text}` (사용자가 마피아일 때 단톡 발언)

### 4.2 동시성 모델
- 게임 세션 = 단일 asyncio 태스크. 상태머신이 순차적으로 페이즈를 진행.
- AI 디스패치는 await로 직렬 (한 번에 한 에이전트). "끼어들기"는 별도 asyncio 이벤트로 다음 디스패치 직전에 체크.
- 스트리밍 LLM 응답은 WS로 청크 단위 전송.

## 5. 에이전트 설계

### 5.1 페르소나 풀 (50개)

이름·직업·성격·발언 스타일을 가지는 페르소나 50개를 `personas.json` 에 저장. 매 게임 시작 시 인원수만큼 무작위 추출 (중복 없음). 페르소나의 직업은 게임 내 역할(마피아/시민/경찰/의사)과 무관 — 의사 페르소나가 마피아일 수 있음.

전체 목록은 부록 A 참조.

### 5.2 에이전트 객체

```python
@dataclass
class Agent:
    agent_id: str           # 게임 내 식별자 (예: "p3")
    persona: Persona        # 50개 풀 중 하나
    role: Role              # mafia | civilian | police | doctor | special
    is_mafia_boss: bool     # role == mafia 일 때만 의미 있음
    alive: bool
    private_memory: PrivateMemory
```

```python
@dataclass
class PrivateMemory:
    role_facts: dict       # 마피아: 동료 id 리스트, 경찰: 조사 결과, 의사: 보호 이력
    public_log: list       # 공개 발언 전체 (모든 에이전트 공통)
    mafia_log: list        # 마피아만 보유 (단톡 로그)
    self_notes: list       # 자기 관찰/추리 메모 (선택, 향후 확장)
```

### 5.3 액션 인터페이스

백엔드가 액션 유형에 따라 다른 프롬프트로 LLM 을 호출. 모든 응답은 구조화 출력 (JSON) 으로 강제.

| 액션 | 입력 컨텍스트 | 출력 |
|------|--------------|------|
| `speak_turn` | public_log, 자신의 역할 정보, 차례 안내 | `{text}` |
| `speak_freetalk` | public_log + 최근 발언자 정보 | `{eagerness: 0~10, text}` |
| `vote_nominate` | public_log + 생존자 목록 | `{target_id, reasoning}` |
| `vote_updown` | public_log + 후보자 최후 변론 | `{vote: yes|no, reasoning}` |
| `last_words` | public_log + 자신이 후보가 됨 | `{text}` |
| `night_kill` (단독 마피아) | public_log + 생존자 | `{target_id, reasoning}` |
| `night_boss_propose` | 마피아 단톡 로그 + 생존자 | `{target_id, reasoning, text}` |
| `night_underling_respond` | 마피아 단톡 로그 + 두목 제안 | `{agree: yes|no, reasoning, text}` |
| `night_boss_dialog` | 마피아 단톡 로그 | `{text, final_target_id?}` |
| `night_police_investigate` | public_log + 조사 이력 | `{target_id, reasoning}` |
| `night_doctor_protect` | public_log + 보호 이력 | `{target_id, reasoning}` |

### 5.4 발언 욕구 휴리스틱 (LLM 호출 없이 계산)

자유 발언 페이즈에서 누구를 다음으로 발언시킬지 결정. 비용 절약을 위해 LLM 없이 점수만 계산:

- 최근 자기 이름이 언급됨: +3 (마지막 2 라운드 기준)
- 마지막 발언 이후 경과 라운드: +N (N은 라운드 수)
- 자신이 투표 후보로 거론됨: +4
- 자기 역할로 알려줘야 할 새 정보 있음 (경찰 조사 결과 등): +5
- 페르소나 가중치 (외향/내향): ±2

라운드로빈 페이즈에서도 동일 점수를 사용해 발언 순서를 정렬.

### 5.5 프롬프트 구조

- **System prompt** (Anthropic prompt caching): 게임 룰 전문 + 페르소나 카드 + 자신의 역할·능력·동료 정보. 한 게임 내내 고정이므로 캐시 적중률 높음.
- **User prompt** (가변): 지금까지 공개 로그 + 자신의 비공개 정보 업데이트 + 현재 액션 지시 + 응답 스키마.

## 7. 테스트 전략

- **게임 엔진 단위 테스트** (LLM mock): 상태 전이, 인원→역할 매핑, 투표 집계, 승리 조건, 동률 처리. 모든 분기 커버.
- **에이전트 액션 통합 테스트** (Claude API mock): JSON 응답 파싱·검증·재시도 로직.
- **밤 시퀀스 테스트**: 마피아 두목/부하 흐름(전원 동의 / 부하 반대 / 두목 최종 결정), 의사·경찰 상호작용.
- **e2e 시나리오** (소수, 실제 API 사용): 4명 미니 게임 1판 끝까지 — 비용·레이턴시·골든 패스 확인.
- **수동 UI 테스트**: 사용자가 모든 역할(시민/마피아/경찰/의사)을 한 번씩 플레이하며 끼어들기·투표·밤 액션 UI 검증.

## 8. 비용 가정

- Haiku 4.5 + prompt caching 으로 8명 게임 1판 추정: 시스템 프롬프트 캐시 적중 시 평균 토큰 비용 X판당 < $0.50 목표.
- 한 판 평균 LLM 호출: 약 (낮 라운드로빈 8회 + 자유발언 4회 + 투표 8회 + 찬반 7회 + 밤 4회) × 게임 일수 4 ≈ 120회.
- 실제 측정은 e2e 테스트로 확보.

## 9. 비결정 사항 / 향후 확장

- 특수 역할 구현 우선순위는 `성직자` > `기자` > `연인`. MVP에는 8~9명 인원 한정 `성직자`만 포함하고 나머지는 별도 이터레이션에서.
- 사용자의 끼어들기에 대한 AI의 동적 반응(예: 끼어든 사용자에게 즉시 응답) 은 MVP 이후 개선.
- 영구 저장·리플레이·통계는 범위 밖.
